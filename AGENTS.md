# AGENTS.md: working on rowan

`README.md` says what rowan does for its users. This file is for working on the engine: how it works, the owner's conventions, tests, commands and switches. It is true at the last commit. It names the code that holds each idea; the doc comments there have the details.

## How rowan works

rowan is a whole-program **abstract interpreter** for Python, written in Rust (`rowan/`). It parses with ruff (private names mangled as CPython does) and walks the syntax tree, running the program on abstract values instead of real ones. Imports run as Python runs them: `TYPE_CHECKING` is False, `import *` and namespace packages work; a module whose code raised is not loaded there, and its next import is unknown code given the module; one a path has no facts of (another run imported it) holds anything there (`import_again`). Every module is a root of the collectors. `rowan/src/interp/README.md` follows one run through the code.

### Values, objects and states

**Values** (`Value`, `domain.rs`) are a set of object ids plus a scalar part (`KeyVal`), which is one of:
* a literal, or up to 64 literals;
* the keys of some objects (`KeysOf`), as they were when taken (`KeysOf::then`, `keys_now`);
* `Data(label)`, an unknown. The label names where it comes from (`row["id"]`, `x.shape[0]`; an operator's or a call's result by its expression, `named_call`), or holds a tensor shape or a builtin type (`typed_label`: `int(?)`; its doc says where types come from).

An unknown joined with None is optional (`optional_label`: `int(?) | None`); a test that removes None gives the type back (`kv_not_none`). Joined with literals, an operator's label loses its name (`max(1, n - 1)` is `int(?)`), and the literals become a *hint* (`8080 | ?`; up to 8, then `hint_sat`). The label alone always covers the value, so code that ignores hints stays sound. Operators, `try_pure` calls (`pure_hint`) and narrowing carry hints (`split_hinted`).

**Objects** (`Obj`, `interp/heap.rs`) are identified by allocation site and context (the call chain; past `CHAIN` (2) sites the older ones are folded into a hash, so contexts stay distinct at any depth).
* A *single* object stands for one runtime object: stores into it are strong.
* Allocating a site again while its earlier object is live gives a *variant* (up to 8), then a *merged* object, whose stores only join. Past 256 objects a site has one summary (16 more for calls the main file's own code makes, `MAIN_CLONES`).
* An instance a call makes where its object is a summary is a strong *recent* object until the call returns or a raise leaves it; then it is folded into the summary (`call_recent`), with what the models' side tables say of it and refer to (`Tables::rename_recent`).
* Garbage collection at returns and at loop and try exits drops the state of the objects made since a mark (`Obj::born`) that nothing reaches (`gc.rs`; an older object given a payload holding other objects since the mark is expanded, once: `Heap::repaid_since`).
* An unread key of an open row holds a *placeholder* per object and key, made where a path first reads it, up to 3 keys deep (`path_placeholder_value`, `mark_found`). A read on more than 8 objects makes one per key instead (`wide_read`).

**State** (`State`, `state.rs`) is what one point on one path knows: names → values; per object its *row* per namespace (`(object, Ns)` → `Row`), its slots (the value under each key), its elements and its length; and the requirements recorded so far.
* Elements are scalars in `elems` and objects in the `Elem` slot, always written together (`add_elem`, `set_positions`); none recorded means not known.
* Lengths have one writer (`set_lens`). A list appended once per round of a loop can have a tensor dim as its length (`sym_lens`).
* The maps are persistent Patricia tries (`layered.rs`): a copy is O(1), a join or diff costs what two states differ in, and writing the value already there copies nothing (`MapValue`). So states stay shared.

**Rows** (`Row`, `domain.rs`) model an object's keys: `present` (may be there) ⊇ `likely` (there unless unknown code removed it) ⊇ `definite` (there on every path), plus `absent` keys, open `sources` (inputs) and `mutators` (unknown calls). A row with neither sources nor mutators is *closed*. A successful read narrows its key in: the program went on, so the key is there.

**The analyzer** (`Analyzer`, `interp/mod.rs`) is a set of components, each with private state in a file of its own (`interp/README.md`). Models, the report and the driver see the `Heap`, their own tables `m` and `api.rs`. `Analyzer`'s doc sorts the components by what a call memo would need: running context (part of a key), state changed outside `State`, output, caches.

### Statements

* **Branches.** A test is evaluated once, into the states where it is true and where it is false (`split`, `narrow.rs`); both branches run and their states join. A pure test that recurs gets its branch rows back (`CondFact`). `"x" in obj.__dict__` (or `not in`) narrows the instance's own attributes, as `hasattr` does, for instances of the program's plain classes (`narrow_member_values`); a `__slots__` instance has no `__dict__`. `k in obj` of an instance whose `in` runs its own dunders narrows nothing of it (`in_by_dunders`; a `__contains__` that is `return k in self.d` narrows `self.d` on one receiver). A failing `assert` raises AssertionError. `match` cases decide on the literal part and the objects apart: a container, dict or plain instance is no literal, and none of the program's classes alone is a mapping.
* **Loops** over at most 16 known items are unrolled: 64 for a comprehension that calls nothing per item, 256 when each item is a distinct object (`distinct_objects`). Other loops run to a fixpoint; past 40 rounds what still changes is widened each round until the head is stable (at most 80 rounds, then as last widened); verdicts and hover values are the last round's (a round's hover facts are rendered only once it stands, from a copy of their state: `PendingFact`; a value's text shows at most 4,096 objects, `RENDER_OBJECTS`). A loop target bound to one of the records a summary or an input's element stands for is a strong *view* per iteration (`bind_views`; changes join both ways, `link_view`).
* **Exceptions** (`tries.rs`). A running `try` (`TryCtx`; its doc lists what may raise) records the state at every point of its body and callees that may raise, joined per exception class. Handlers start from the raises they may catch; the rest go on through the `finally` to the enclosing try. A raise every handler around surely misses leaves the program: it is recorded once whatever its class, and its `finally` runs once from those states joined (`leaves_program`). A raise no running try sees is not recorded (`TryCtx::sees`). An object a raise leaves half-built is dropped unless the path holds it (`drop_unreached`; also through payloads given since). A raise in the `else` or a handler passes the handlers by but not the `finally` (a try context catching nothing takes it there). `with` is a `try` whose `finally` is `__exit__` (`with a, b:` is `with a: with b:`; `async with`: `__aenter__` / `__aexit__`, awaited); a `finally` runs on every way out.

### Calls

Every call of the program's code runs the callee's body at the call site (`calls.rs`), in a context of its call sites (`CHAIN`, 2, written out; older ones hashed). Defaults are what `__defaults__` / `__kwdefaults__` hold once read or set; a parameter `**kw` may supply (an open mapping: one of keys not all known) is what it may hold there or the default. An operation on several receivers whose code runs is one alternative per receiver; past 4, the instances of one class are one (`per_receiver`). The program's decorators (functions, classes, instances; not a followed package's classes) are called with the function; one rowan does not model leaves it `opaque`, and a class it decorates open (its instances may have any attributes: `@attr.frozen`). A value that may be several callees calls each on a state of its own (`call_value`).
* **Budget.** Each function code (all closures of one `def`) may run 4,096 statements in all (`Budget`). Past that its calls do not run (`skipped_call`): they are unknown calls that may also change what the function's code reaches. `effects.rs` decides what, from `flows.rs`'s reading of the function's text: the globals, cells, defaults and arguments it may change, keep or give away (`Level`, `Flags`, `KeptPlace`); class attributes by name (`result_classes`); a receiver by the names its code uses (`receiver_effects`; what it surely stores, `must_stores`; their values where its text says them, `stored_value`); a method read off an argument and called (`o.m(…)`, `getattr(o, "m")(…)`, `f = o.m; f()`: `Level::Bound`) changes it; the program's instances the arguments reach whose dunders change something are given to it (an operator, `len`, `str` may run them); the result (`returns_params`, `returned_aliases`). Such a function also gets a reporting run with open parameters. Entry runs are not counted (one per function), so work is bounded by functions × budget.
* **Recursion** (`Recursion`). A recursive call uses the running activation's partial result; the activation reruns, also from its recursive calls' heaps, until its result and heap are stable (its own names aside: `same_but_names`), 8 rounds, then widens. Activations are told apart by call site and context (4 deep), with literal arguments also by those literals (40 deep). A call of itself on nothing but the innermost activation's arguments or outside data joins that activation, past one level (`recursion_without_progress`). A recursive call raises what its activation raised in its rounds (joined per class), where a try of the activation's frames that may see them runs around it (`collect_rec_raise`): from the call's own state joined with what the raise state says of the objects present there; more than three classes as one of any class, joined once per round.
* **Result summaries** (`summary.rs`). A skipped call gives back what its function returns for any call, as a *shape*: literals, typed unknowns, and the records made in that run. At the main module's call sites the records are made anew (`materialize`: up to 16, 4 deep); elsewhere only the scalars, by type. A record the run did not make for itself (`escaped`) is `any`. Shapes come from a second analyzer (`summary_source`, `shape_for`); not used where the call is given instances whose dunders change something (that run's parameters are none). A getter's skipped call gives the attribute it reads (`getter_result`).
* **Unknown values** are never taken for the program's instances: their methods are unknown calls given the receiver (`x.copy()` too; `o.m` read then called: `Heap::attr_of`; not an instance's whose library bases are builtins or torch modules), as are `sort` / `reverse` / `remove` / `insert` and a dict method of one holding attributes; a str method's name gives a str only on one typed `str` / `bytes`. A read, `del` or attribute read of an unknown scalar part (an element unpacked from an unknown, an operator's result) may raise anything into a running `try`, as may `-x` / `~x` of an unknown and an item store into one (`untyped_operand`); `in` an unknown and iterating one may raise TypeError, an attribute store on one AttributeError, `d.update(x)` of one TypeError or ValueError. A parameter annotated with a TypedDict is a dict. An unknown a library call made has no dict or str methods (`Obj::opaque`). An attribute stored on an unknown on some paths keeps, on the others, what it had. An instance unknown code changed may hold any name its class has (not a method or class); where that code may have removed an attribute, the class's `__getattr__` is a call that does not run.
* **Unknown calls** (`unknown.rs`) may change everything they reach through what they are given (`f(*xs, **d)`: their items, in a new tuple and dict, not xs or d: `unpacked`), at any depth: records get a mutator, slots may hold anything (the shared unknown object, which no store changes, `escape`), lists and sets any items and length. A class attribute the code may `del` may be gone after. NamedTuples, patterns, matches, paths, frozensets and enum members' name and value cannot change. What they reach may run: the program's functions and a module's code (`follow_code`), instances' dunders that change something (`changing_dunders`, `construct_dunders`), generators (`unknown_runs_generators`). A walk from the same values redoes only what changed (`Havoc`). The result is an unknown, whose items may be those of the mappings the call was given (`unknown_result_rows`); `a + b` of unknowns has either's elements. The call may raise anything.
* **Library functions** known to have no effect are `noeffect` (`ALLOWLIST_PREFIXES`), unless they change their arguments (`random.shuffle`) or are given code they may call (`CALLS_GIVEN`, `LOOKS_AT_CODE`); given the program's instances, their dunders may run (`library_dunders`). `random.choice` / `sample` give back the items. A library call's `*xs` / `**kw` of known items and keys are its arguments; a `*xs` of items not known makes the call unknown unless its model reads `*xs` itself (`Registry::reads_stars`), a `**kw` of keys not known a standard-library model's (`spread_stars`).
* **Builtins** run the dunders Python calls for them (`builtin_dunder`; `x in xs` an instance's `__eq__`, item by item over known items, else as a skipped call: `in_runs_eq`; `-x`, `xs[x]`'s `__index__`, `x in obj`'s `__contains__` (on instances whose attributes are known; else as library code), hashing's `__hash__`, `del x.a`'s `__delattr__`, unpacking's `__iter__`; what builtins and container methods that compare, hash, add, iterate or print items run of them, as library code, those dunders only, no `__eq__` in hashing for a class that hashes by identity: `driven`). An instance of a class of the program's alone (`plain_program_class`) lacking the protocol raises TypeError (`x[k] = v`, `del x[k]`, `with x`, `in`, iteration; unpacking on its own path, `without_dunders`), as an Enum member's subscript does (another library-based instance's may raise anything), and an item store into an input's object may. `len`, `hash`, `int`, `float`, `str` and `repr` give their type (`kv_of_type`). A builtin without a model is unknown code. A plain function of the program has what was stored on it (`plain_function`, `escaped_fns`). TypeErrors come from builtins given wrong types (`takes_types`, `sure_type_error`), from hashing (`check_hashable`), from iterating a number or None (`iterable_part`, in `iterate`), `**` of no mapping (`mapping_part`), subscripts by the wrong type, item stores and `del`s a str, tuple or set refuses (`item_write_part`), format specs a value rejects, and arguments that do not fit a function's parameters (`args_fit`; not where a model calls it); ValueErrors from pairs that are none (`pairs_part`: `dict("ab")`) and `a, *b = []`; TypeErrors from `sort` / `min` / `max` of items of kinds that do not compare (literals and containers: `incomparable`); AttributeErrors from attribute stores on builtin containers and typed unknowns.
* **Mixed values.** Operations on literals beside objects (`"a" if c else [1]`) run on each part (`split_mixed`, `with_rest`); beside an unknown object, which may be them, the literals are no key and no model's argument (`opaque_key`). None raises where Python rejects it (operators with literals or builtin containers, calls, subscripts, attributes, `len`; `in` None or a number, a str of a non-str). A name an imported module does not bind (not one a model wrote), a module's attribute it does not define, or one a function was not given, may raise there; the path goes on; a global bound on some paths raises NameError on the others, in functions too, and one the main module binds further down surely. A module's `__dict__` is its namespace (a missing key a KeyError). A `cached_property` cached on some paths runs its getter on the others. A property is a data descriptor while its class holds it on the path: its getter takes the read over the instance's own value, its setter (or the refusal) the store (`Heap::prop_names`); `name = property(fget, fset, fdel)` in a class body of one function each is one (`class_property`); any other `property(…)` an instance of the pure-Python `property` (`m_property`), whose `__get__` calls whatever the getter may be; so is an object whose class has `__set__` or `__delete__` (`is_descriptor`); a descriptor read through its class runs `__get__(None, cls)`, `hasattr` its getter. A `__slots__` member not shadowed (`slot_member`) hides a `__dict__` entry of its name: one stored there is weak, the slot's value no entry of it. An own value on some paths beside a method or descriptor of the name: the class's read on the others.
* **Entry runs and general runs** (`entry.rs`). Functions the main run does not call (also those only entry runs call) run with open parameters (`param F.x` schemas) from the module's end; a called function gets a requirement-only run so too. A *general run* (`Entries::general`) gives a hover's value for any call (`Fact`), apart from the program's own calls. It starts from `after_any_code`: the module's end after any of the program's functions ran, joined with the heaps at module code's calls. Parameters are as annotated (`annotations.rs`, `Heap::ann`): `x: C` an instance of C or of a subclass overriding something of C, each made as C's is (up to 2 subclasses; past them an unknown instead, `isinstance` of which is undecided: `is_subclass_stand_in`; C's own stands for the plain subclasses' too, `Obj::any_sub`: `type(x)`, `isinstance(x, Sub)` undecided), with None where the annotation allows it; `x: E` of an Enum its members; a union member by member as a field's (`param_from_members`: a `Literal`'s values, `int | str` an unknown of each type, a class's instance), an alias the module binds once, or imports from a module of the program that does, as what it names (`alias_of`); `*args: T` / `**kw: T` items of T (a `**kw` dict's keys strs while its code neither changes nor passes it: `Heap::str_keyed`); an annotation that raises is no value (`eval_annotation`). Such an instance, and a method's receiver, may be any of its class's instances, one the program made too, and another argument: no identity key, `is` / `==` / `in` by identity undecided (`Obj::arg`, `may_be_same`). A container annotated `list[int]` (`set`, `dict`) is so as the call starts: what the function puts in it after joins its items' reads (`put_items`; a dict's keys beside a key of another type as an object of their type, `5 | str(?)`: `annotated_keys`); what any part following one annotation is given (by unknown code too) joins every such part's (`Heap::ann_put`). A parameter is as its own `def` annotates it (not as an `@overload` stub of the name did). An attribute the program's code stores beside `__init__` holds `__init__`'s value or what those stores put there where their text says (`AttrStores`, `stored_value`: literals, one builtin type, `+= 1` of ints; anything beside those literals once a store's value is not said or attributes may be stored by names or ways not written out — `setattr` of a computed name, a `__dict__` or `vars()` changed or given away — on an instance of a class such a store reaches: the receiver's, an annotated parameter's, `C()` made there, else any: `StoreTarget`, `Computed::reaches`), over a class-level default too. A method runs on any instance of its class or a subclass (only an `nn.Module`'s on its own class's; `__init__` of a class without subclasses on a new one, `new_instance`), a classmethod on the class or a subclass. A closure's cell its run's state holds nothing of (a run for any call) is an unknown.

### Generators and iterators

* **Generators** (`gens.rs`) run whole at their first consumption (`force_gen`), in the creating call's context; `iter()` runs nothing. Its activation is its own object (never a variant: `yield_value` finds it by site); the items a path gives before it surely raises are a consumer's too (`raised_items`). A consumer of item *k* sees the effects up to yield *k* (`GenEffects`). If code between items changes what the generator reads after a yield (the containers its loops iterate count; changes by the time it asked, also where it ends nowhere), it runs again with that change (`note_resume`, `with_gen_restart`; each consumer state is joined once per generator, the runs watched since sharing it: `Gens::resumes`).
* A generator expression is a generator of `iter()` of its first iterable (`FuncNode::GenExp`). One whose items are all taken before any other code runs is run where it is written, as a comprehension (`Scopes::eager_genexps`): unpacked, or given whole to a builtin taking every item at once whose name no scope around binds (`syntax::Bound`: a program's own `sum` may take none); given to a method or a library function, by what the callee is at the call (`bulk_genexp`).
* `@contextmanager` bodies run at their yield; the body's `return` / `break` / `continue` run the generator's rest first (`CmHook::jumps`). `any` / `all` / `next` / `in` of a generator made for them stop it where an item decides (`stopearly.rs`).
* A generator dropped before its end is closed: GeneratorExit is raised at its yield (`genclose.rs`: `closing_loop`, `close_unheld`); a handler of its own that catches it marks its path (`\u{1}closing`: re-raised, ended, or yielding again, where `close()` stops it). Its raises happen where the consumer asks for the item it fails to give (`genraise.rs`, `exhaust_whole`). Where the program's text calls `.throw(`, a run whole also raises an exception of any class at each yield inside a try of its own, so its handlers run (`thrown_class`; what leaves its body is the `throw` call's, an unknown call's).
* **Coroutines** (`async def`) are lazy generators without items (`make_lazy_gen`): the body runs where the coroutine is awaited, by `await`, `asyncio.run`, `gather`, `wait_for` (`await_value`, `run_coroutine`); never awaited, never. A task (`create_task`) may run at any later `await` and before `asyncio.run` ends; one that suspends itself interleaves, as a call that does not run (`coroutine_steps`; in `gather` too, unless the code it reaches, callees too, writes no global, cell or argument: `writes_nothing_shared`). One given to library code may run there, later as a task, or never (`force_gen`). A framework's entry runs call coroutines as awaited (`as_framework`).
* A `for` calls a user iterator's `__next__` each round (`for_user_iterator`; `async for`: `__aiter__`, then `__anext__` awaited); over a one-shot iterator its body also steps, each round takes the item where it stands (`for_stepping`).
* **One-shot iterators** (generators, `iter`, `map`, `filter`, `zip`, `enumerate`, `reversed`) have a cursor from creation (`start_iterator`). Whatever takes items takes them from the cursor and moves it (`items_from_cursor`, `positions_left`, `cursor_alternatives`); they have no `len` and no subscripts. A `map` calling the program's function gives what its calls change item by item (`effects_per_item`, as a generator's `GenEffects`). One over a list, dict, set or deque is *live* (`Tables::live_iters`): if its containers changed, it takes its items again (`sync_live`; inside a refill of the same sources, items not known), and a dict's, set's or deque's whose keys changed raises RuntimeError. Used up, it stays so.

### What rowan reports

* **Requirements** (`access.rs`, `guards.rs`). Reading a key from a row open through an input records a requirement on the input: `always` (every path) or `sometimes`, and `only_if` the tests of the function's parameters, as passed, that all its readers passed (`State::path`). A read in a `try` whose handler catches its `KeyError` is guarded (`is_guarded`; a catch-all guards only its own function's reads). A read on one of several objects needs each one's key only sometimes (an element's: per element). A general run's requirements on its own parameters are a hover's contract (`Findings::contracts`); a parameter's fact keeps what each call passed (`Fact::passed`).
* **Verdicts** (`classify`, `domain.rs`). Every read, `del` and `pop` gets a tier per object from its row. `proven`, `possibly`, `missing` and `input` are sound; `likely` and `likely-missing` are optimistic (they assume unknown code removed nothing). In one of several functions a value picks (`cx.picked`), `missing` becomes `possibly`. A key of a record filled from data (`Tier::Map`) is not reported alone; beside other objects it may fail.
* **Models** (`models/`, by qualified name in `Registry`) are functions of `&mut Analyzer` that see the `Heap`, their tables (`models::Tables`) and the interpreter's public methods. They compute CPython's result on known values (str, formatting, json, re, datetime, decimal, sqlite, csv, files, `lru_cache`, …) and simulate pandas columns, pydantic and FastAPI validation and routing (a raise of any class may be a validator's ValueError; past a skipped call, a handler's HTTPException), and torch and numpy shapes (dims as polynomials). `models/README.md` says what each file covers.

### Limits: deadline, on demand, the server, installed packages

* **Deadline** (`ms`, 10 s) is a safety net; the budget bounds the work. Time in followed packages' code is not counted (they have a share of their own). Past the deadline the program's calls are unknown, running ones stop, and entry runs are left out (`Budget::hard_cut`). The same happens past 1.5 GB of resident memory (`MEMORY_MB`, `over_memory`; a thread looks every 10 ms, `memory_watch`), which grows with the time an analysis runs. A golden document records each line's different observations once (`add_row_check`).
* **On demand** (`on_demand`, `general_run_of`): a hovered function's general run with verdicts, from the module's end (`demand_start`), with a fresh budget. Past `fanout` (4) budgets of work, its callees' calls do not run (`Budget::hover_cut`; several callees: one `skipped_calls`).
* **`rowan serve`** (`serve.rs`) starts the whole run and a module-code run together. It answers with the whole run's document if that completes within `EARLY` (1 s), else with the module code's, and the whole run's follows as an event. With `--follow`, a run that follows packages starts too and its document replaces the answer. A changed file, a newer request or a `cancel` cuts the analyses running for it (`Budget::cancel`).
* **Installed packages** (`--follow PKG|*`, `library.rs`; from `--site-packages`, `$VIRTUAL_ENV` or a `.venv` above the file) run as the program's code, with per-function budgets. Each entry of the program into them (an import, a call) has an allowance of work (`fanout` budgets) past which its calls do not run; module code goes on. Large closures of such calls are shared (`LibClosure`, past `SHARED_PAST` walk visits). All entries share the library's share (`LIB_SHARE`, half the deadline): past it the running entry is undone (`cut_body`, `forget_since`) and no library code runs any more. Calls of *inert* code still run (`inert::inert`). A class whose followed base's `__init_subclass__` does not complete has an open base. Followed code's own verdicts are not reported.
* **Deferred definitions** (`deferred.rs`): an imported module's `@d def f` whose decorators are all plain inert code runs them when `f` is first read, not at the `def`.

### Soundness

What rowan claims holds relative to the models and to annotations: of values whose class is unknown; a general run's `x: int` is an int (not a subclass overriding its operators); an unknown the program gives an annotated field, or an attribute its class declares (`count: int`, `self.size: int = …`: `attr_as_annotated`), is of its type (`field_as_annotated`), as a pydantic field's validated unknown is. Also assumed or ignored:
* `getattr` by a name not known reads every attribute of the program's objects, quietly; known in part, those whose names fit (`Payload::Affix`, `template_affixes`: f-strings, `%`, `.format`, and `"on_" + m` while no program class defines `__radd__` / `__add__`; a library's keeps the text; what an object holds under names not known, any where unknown code may have added some or the value is not known); a container's, or past a wide read, one method per call site.
* `exec`, `setattr` with unknown names on a class, metaclasses and monkey-patching (rebinding a function or class too) are unknown or ignored. A module's function the program calls only by name has no other callers. Unknown code does not shadow a class attribute on an instance of a library-based class. A library base's methods keep the attributes of an instance whose library bases are builtins or torch modules (`model.train()`, `to`, `state_dict`).
* An unknown beside objects is no instance of a class. `isinstance` against a builtin class decides by type (undecided: `True | False`), and narrows literals and typed unknowns (`int(?)` not against `bool`: `kv_isinstance_narrowed`). A builtin's name the program binds is its function, not the builtin: tests narrow by what the callee was (`narrow_call`), and `flows.rs` reads a name the module or an enclosing function binds as a call of the program's (`Flow::builtin`; names an `import *` binds are not counted).
* List lengths are tracked up to 15 (a few per path, each with its positions; `xs[:n]` keeps `xs`'s). An object a path has no facts of reads as unknown (`read_row`). A set's items, and a dict's whose order depends on the path, have no order (`Iteration::items`, `any_order_items`).

## Working conventions (the owner's standing instructions)

* Python runs only through `uv run --no-project python` (3.14 pinned), for the test harnesses.
* **New test cases are specifications.** Write the expected rows and verdicts by hand from the program text first, then make the engine produce them. Never derive an expectation from engine output. When an expectation turns out wrong, fix it with a comment saying why, keeping the line count. Value analysis matters more than bug-finding verdicts.
* **Hypotheses need a repro.** For a suspected bug or slowdown, first a small program showing it (a golden case; `#@work` / `#@tabulations` bounds for cost), then the fix, then measurements.
* **Soundness first.** Where the runtime oracle and this file disagree, the oracle wins. Golden cases matter; snapshot changes are fine when sound.
* **Commits.** Commit when a round of work is complete and golden, snapshots and `cargo test` pass; never commit a failing state. Review snapshot diffs before `--update`.
* **Plans.** When a request mixes several things, write the plan first, then work it in order. Keep this file under 200 lines and up to date with every change.
* **Output is for Python engineers.** The report, hovers and diagnostics use words and Python access paths (`row["id"]`, `items[*].sku`), never engine terms (row, tier, source, placeholder) or internal site labels (`report::site_text`). The hover layout is `renderHover`'s doc (`vscode-rowan/extension.js`): values as typing writes them (`None` last), Notes explaining rowan's own notation only (not `list[x]`), and a function analysed on demand noted only when that run was cut; `vscode-rowan/test.js` checks real hovers.

## Debugging switches

* `ROWAN_DEBUG=1`: body runs (`run F at SITE`), skipped calls, entry runs, each library entry's work, the functions doing most (runs, own statements, units and ms of outermost runs), and a `work:` line of counters: statements, units (statements + walk visits / 16; walks: reachability and closure walks), body runs, objects, row joins, visits, havoc visits, verdicts, facts, and which cut ended it (deadline, memory). ## Layout (`rowan/src/`, ~82k lines: the engine ~38k, the models ~45k)

The folder READMEs are maps of the code, file by file, with a reading order: `rowan/README.md` (the crate, the binary, `py/`), `rowan/src/README.md` (syntax, domains, `main.rs`, `serve.rs`), `rowan/src/interp/README.md` (the `Analyzer`'s components, how a program runs), `rowan/src/models/README.md` (what a model is, a file per library). In short: `frontend.rs`, `scopes.rs` and `syntax.rs` parse; `intern.rs`, `domain.rs`, `source.rs`, `layered.rs` and `state.rs` are the domains; `interp/` interprets (`report.rs`, `render.rs`, `facts.rs`: the output); `models/` are the libraries; `rowan/py/` is a PyO3 binding (it does not load on macOS 26). `vscode-rowan/` is the editor extension; it talks to `rowan serve`.

## Implementation rules that are easy to break

* **Models allocating several objects at one node** must give each its own context (calls: `Node::sub`; a field's factory: `factory_site`).
* **Callees** run with the caller's `state.exits` taken out and restored (`take_caller`, `give_back`; case y438).
* **GC roots.** A side table keyed by objects goes into `side_edges` (and must hold for a recent object's summary too: `Tables::rename_recent`). Anything else the analyzer holds (a running `with`'s managers) goes into `gc_pinned`. Otherwise a read gets an empty row, and a list no length.
* **Generator yields** use `alloc_raw` for per-yield states. **Stdlib objects** (`stdobj.<kind>`) keep their state in Attr slots (`m_stdobj`). **Attributes resolved by class** (`class_resolves`): class, model and `__getattr__` objects have more than their rows show.
